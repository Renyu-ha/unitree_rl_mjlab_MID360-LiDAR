# Go2W model source

Based on [ZhongL1/unitree_rl_mjlab_go2w](https://github.com/ZhongL1/unitree_rl_mjlab_go2w/blob/fe0deeaef2e6e579db63b782f1082b5d2b4ed071/mjlab/asset_zoo/robots/unitree_go2w/xmls/go2w.xml), commit `fe0deeaef2e6e579db63b782f1082b5d2b4ed071`. The underlying Unitree model retains the adjacent BSD-3-Clause LICENSE; the reference configuration code is Apache-2.0.

`xmls/go2w.xml` is the single final model. Collision names, four wheel-hub sites, visual-only wheel duplicates and the three sensors (`imu_ang_vel`, `imu_lin_vel`, `root_angmom`) are defined directly in it. The angular momentum reward is disabled for testing; its `root_angmom` sensor is retained so the reward can be restored independently. There is no runtime XML adapter, source copy or model manifest.

The 14 meshes actually used by geometry are stored in `xmls/assets/`, unchanged from the source. Unused `calf_mirror_0.obj`, `calf_mirror_1.obj` and `foot.obj` are removed. Link transforms, masses, inertias and joint axes/ranges retain the reference values.

For the wheel-contact experiment, the four named wheel collision meshes are replaced directly in the XML by cylinders. Each cylinder has radius 0.086 m and half-width 0.025907457 m, matching the original mesh's radial extent and axial bounding box. Its centre is at body-local Y = +0.050764256 m on the left and -0.050764256 m on the right; its local Z axis is rotated onto the wheel joint's Y axis. The wheel visual mesh remains unchanged and does not collide. Explicit wheel mass (0.98 kg) and inertia are retained rather than recomputed from cylinder density. Control gains, torque limits, armature, friction, solver settings, sensors and self collision are unchanged by this experiment. Commit `6ff9526` is the pre-cylinder revision; its robot model matches `63ec8cb`, used for the compiled-model comparison. See the [contact survey](../../../../doc/wheeled_contact_survey_zh.md) for source comparisons and experimental limits.

`get_spec()` only loads the final XML and embeds its mesh files. Initial state, KP/KD, action scales/order, rewards, observations and PPO remain in the existing training configurations. Self collision stays enabled. The MID360 is represented by ray sensors; hardware payload mass/extrinsics still require calibration.

The 51.815 mm cylinder width preserves the original mesh's full axial bounding box, not its rounded tread profile. It is about 15.14% wider than the 45 mm cylinders declared by the surveyed HIMLoco, DreamWaQ and public robot_lab Go2W URDFs. A straight cylinder also fills out the original mesh's rounded shoulders. The survey records geometric cross-section measurements and a proposed 45 mm width-only comparison; the current XML has not been narrowed.

Wheels now use mjlab's `BuiltinVelocityActuatorCfg`, with damping 2, effort limit 45 Nm and armature 0.0 as requested. `src/utils/mjlab_compat.py` applies the continuous-joint range handling used by the reference repository's [velocity factory](https://github.com/ZhongL1/unitree_rl_mjlab_go2w/blob/fe0deeaef2e6e579db63b782f1082b5d2b4ed071/mjlab/utils/spec.py#L204-L213): no inherited control range or control clipping on an unlimited joint. The Go2W asset package enables it at import in each process, including workers importing a pickled `spec_fn`, without modifying installed dependency files. The previous custom wheel actuator is removed. Following the user's G1 comparison, policy action clipping is disabled (`clip_actions=None`), as in this repository's G1 tasks. Wheel targets are `20 * action` rad/s; 20 is a scale, not a speed limit. Torque limiting remains in the native actuator. The [G1 alignment record](../../../../doc/go2w_g1_alignment_zh.md) describes the separately updated training, sensing and randomization settings.
