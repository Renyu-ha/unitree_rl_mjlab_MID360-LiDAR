# Go2W model source

Based on [ZhongL1/unitree_rl_mjlab_go2w](https://github.com/ZhongL1/unitree_rl_mjlab_go2w/blob/fe0deeaef2e6e579db63b782f1082b5d2b4ed071/mjlab/asset_zoo/robots/unitree_go2w/xmls/go2w.xml), commit `fe0deeaef2e6e579db63b782f1082b5d2b4ed071`. The Unitree model retains the adjacent BSD-3-Clause LICENSE; reference configuration code is Apache-2.0.

Two static entry models share `xmls/go2w_common.xml`, which owns the body, assets, collision names, wheel-hub sites, visual-only meshes and the three sensors (`imu_ang_vel`, `imu_lin_vel`, `root_angmom`). `get_spec()` only loads the selected entry through native MuJoCo XML includes. The angular momentum reward is disabled; its sensor is retained. The 14 used meshes are unchanged from the reference; unused meshes are removed. Link transforms, masses, inertias and joint axes/ranges retain the reference values.

`go2w.xml` selects cylinder wheels (default). `go2w_mesh.xml` selects the original `wheel.stl`, with the reference left/right poses matching the visual wheels; mesh collisions use the convex hull. To switch every Go2W train/play task, change `GO2W_XML = GO2W_CYLINDER_XML` to `GO2W_XML = GO2W_MESH_XML` in `go2w_constants.py` and restart the process. There is no CLI switch. Both entries use zero wheel margin and `condim=3, priority=1` directly in XML.

The cylinder entry uses radius 0.086 m and half-width 0.0225 m (45 mm full width). Centers are body-local Y = +0.050764256 m on the left and -0.050764256 m on the right; cylinder Z axes are rotated onto the wheel joints' Y axes. The mesh entry keeps the original approximately 51.815 mm axial width. Visual meshes remain unchanged and do not collide. Explicit wheel mass 0.98 kg and reference inertia are retained. The previous 51.814914 mm cylinder width is recorded at `4699c76`; the pre-cylinder model is at `6ff9526`. A straight cylinder does not reproduce rounded tread shoulders. See the [contact survey](../../../../doc/wheeled_contact_survey_zh.md).

Training configuration owns initial state, controllers, actions, observations and rewards. Nominal root height is 0.4 m. Leg PD gains, limits and armatures follow the reference; wheel `BuiltinVelocityActuatorCfg` uses damping 2, effort limit 45 Nm, armature 0 and frictionloss 0. All actuators explicitly use frictionloss 0. Native continuous-joint support replaces the former compatibility patch. Action clipping is disabled; wheel target speed is `20 * action` rad/s with native torque limiting.

Self collision is enabled. All collision geoms use zero margin. Non-wheel geoms use base sliding friction 1 and task overrides `condim=1, priority=0`. Wheels use base friction `0.8 0.02 0.01` and `condim=3, priority=1`; task friction randomization remains active. Zero box margin avoids the MuJoCo-Warp 3.16 native CCD/MultiCCD limitation; both CCD features retain their defaults. Changing wheel margin from 0.001 to 0 changes contact activation distance; controller gains, stopping tolerances and solver budgets are retained.

Global options belong to the scene. The reference XML's `cone="elliptic" impratio="100"` declaration was removed because training already used the parent scene's `pyramidal/1`. Shared velocity tasks retain solver/linesearch budgets 50/100 with unchanged stopping tolerances and warnings. All Go2W train/play resets enforce conservative terrain clearance of 5 mm plus collision margins by lifting only environments that need it. This does not guarantee zero penetration during later motion.

The installed backend is the pinned MuJoCo-Warp 3.16.0.post1 fork with upstream fixes #1771/#1796 and EPA capacity 64; see [installation and validation](../../../../doc/setup_zh.md). No runtime XML adapter or installed-source patch is used. MID360 is represented by ray sensors; hardware payload mass and extrinsics still require calibration. Task alignment details remain in the [G1 alignment record](../../../../doc/go2w_g1_alignment_zh.md).
